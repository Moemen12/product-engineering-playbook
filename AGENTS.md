# Repository Guidelines

This repository contains a reusable product-development and database-design playbook. It is intentionally project-agnostic and should remain understandable to developers, product managers, designers, and interview candidates.

## Writing principles

Use simple English and explain each technical term the first time it appears. Prefer practical examples over abstract theory. Separate confirmed information from assumptions. Keep the core guidance framework-oriented rather than tied to a specific company, sport, framework, database, or cloud provider.

## Scope principles

The playbook should help a team move from an unclear product idea to a small, testable product. It should cover product discovery, core user journeys, MVP scope, domain modeling, database design, failure cases, and technical tradeoffs. It should not prescribe one technology stack or imply that every product needs the same architecture.

## Maintenance principles

When adding guidance, preserve the distinction between the product domain, user interface, application behavior, and persistent data. Prefer short checklists, tables, examples, and reusable templates. Update the relevant template when a new recurring practice is introduced.
